# 关键词 vs 语义检索对照（2026-09-10）

`python eval/run_retrieval_check.py --output <dir>`，语料 `examples/knowledge/ops`
（7 个片段），k=3，语义模型 `BAAI/bge-m3`（硅基流动，OpenAI 兼容 `/v1/embeddings`）。

## 结果

| 方案 | Recall@3（同义问句 13 条） | 误检（不相关问题 8 条） |
|---|---:|---:|
| 关键词基线 | 9/13 | 0/8 |
| 语义，下限 0.5（默认） | **12/13** | 1/8 |
| 语义，下限 0.35（原设计） | 12/13 | **6/8** |

下限 0.35 那一行的完整报告在 [`../retrieval-2026-09-10-floor-0.35/`](../retrieval-2026-09-10-floor-0.35/report.json)，
由同一份代码、同一语料、同一题集产出，只改了 `--min-similarity`。

## 召回：语义救回了关键词漏掉的 4 条中的 3 条

关键词漏掉的 4 条全部与文档**字面零重合**：

| 问句 | 文档里的写法 | 关键词 | 语义 |
|---|---|---|---|
| 内部测试的号算不算进去 | 测试账号 | ✗ | ✓ |
| 同一个人买两次算几个人 | 去重用户数 | ✗ | ✓ |
| 交易额归到哪一天 | 归属到下单日期 | ✗ | ✓ |
| GMV 按什么状态统计 | 成交额 | ✗ | ✗ |

语义的漏检是关键词漏检的子集——这组题上没有出现"关键词能找到、语义找不到"。

仍然漏掉的「GMV 按什么状态统计」：正确片段在语义排序里是**第 4 名、0.339**，排第一
的只有 0.390。英文缩写与中文业务名之间的桥，bge-m3 在这里没有搭上。值得一记的是
`metrics.yaml` 里 `gmv` 的别名本来就写着「GMV / 成交额」，但文档检索没有用到指标
别名——这是一个观察，本次没有据此改动检索。

## 误检：余弦下限是模型的属性，不是代码常量

语义检索会给任意两段文本打出非零相似度，所以必须有下限，否则"没有相关证据"永远
不可达。原设计取 0.35，**在假向量测试里全部通过**；拿真模型一量，8 条不相关问题
里有 6 条越过下限——「今天天气怎么样」以 0.429 拿回运营手册。

实测分布（同一语料）：

- 同义问句的正确片段：最低 **0.535**，最高 0.790（不计上面那条 GMV 漏检）；
- 不相关问题的最高分：最低 0.258，最高 **0.549**（「客服响应时长怎么算」→ 成交额）。

**两个分布是重叠的**：有一条不相关问题比一条正确证据得分还高。所以不存在能把两者
分干净的单一阈值。取 0.5 的理由是：它在这组题上保住了全部 12 条正确命中，同时拒掉
8 条不相关里的 7 条。代价是剩下那 1 条误检，以及正确命中的余量只有 0.035。

下限因此改为 `knowledge.embedding.min_similarity` 配置项；0.5 只是针对 bge-m3 的
默认值，换模型必须重新标定。

## 这组数字能说明什么、不能说明什么

- **同义问句集在测量前已冻结**：`eval/knowledge/paraphrases.yaml` 于 2026-09-09
  20:18 随提交 `5ee4784` 入库，语义结果 2026-09-10 才测得，其间未改动。
- **误检率是样本内数字**：不相关问题集写于 2026-09-10、写下时尚未看到分数；但默认
  下限 0.5 是看过这组分数之后选定的，所以 1/8 不能当作泛化表现。
- 13 条 + 8 条问句、7 个片段、单次运行，**不支持任何统计结论**。它展示的是一种
  取舍——语义检索用 1 条误检换回 3 条召回——而不是"语义检索更好"的证明。
- 关键词与语义分别报告，**不合并成一个"RAG 准确率"**。
- 分母只含该主体有权且适用的证据；与 BIRD 封存 test200 无关，未读取、未侵入。

## 复现

```bash
export QUERYAGENT_EMBEDDING_API_KEY=<key>
python eval/run_retrieval_check.py --output eval/results/retrieval-<日期>
python eval/run_retrieval_check.py --min-similarity 0.35 --output eval/results/retrieval-<日期>-0.35
```

输出目录已存在时脚本拒绝运行，不覆盖既有证据。每次运行会重建 `index.db`（含语料正文
与向量），该文件不入库。嵌入调用会把语料正文发往上述端点——本语料是合成电商文档。
