# 切片 1C-2：结果说清覆盖了什么、按什么分、文档依据是否真的执行了

日期：2026-09-10。状态：计划（验收标准在实现前固定）；已实现，结果见 §8。承接 v0.7.0。

## 1. 为什么做这一刀

v0.7.0 让「上个月」真的进了 SQL，但真机上还剩四处答不上来的地方，都在
[v0.7.0 map](../wayfinder/v0.7.0-map.md) 的「Not yet specified」里写着：

1. **说不出数据截至哪天。** 演示数据止于 2026-08-22，9 月问「上个月」只算到 8 月 22 日，
   「本月」为空——系统把不完整月当整月报，把"没有数据"和"业务为 0"混在一起。
2. **不能分组。** 「上个月每天的新增用户」「各渠道的新增用户」是最常见的取数问法，现在
   只能得到一个总数，而且系统不会说它丢了"每天"两个字。
3. **日期是拼进 SQL 的。** ADR-008 用类型化编译顶住了第一刀，但它自己写明：值的种类一
   多就该改成参数绑定；而且字面量格式是按方言的兼容承诺——1C 已经因此漏过每个区间的第一天。
4. **文档规则与执行互不相认。** 确认单上「文档依据：按注册日期计数」和执行的「首单口径」
   可以同时出现，结果行只能说"系统不核对两者是否一致"。

## 2. 已定的设计取舍

| 编号 | 取舍 | 理由 |
|---|---|---|
| E01 | Connector 协议加 `params`，SQL 一律用 `?` 占位（DB-API qmark）；各连接器自己转成驱动的写法 | 编译器与存储只认一种中性形式；方言知识留在连接器里。PyMySQL 与 clickhouse-driver 都是 `query % 参数` 客户端替换，**传参时 SQL 里的 `%` 必须成对**，由连接器按 sqlparse 词法统一处理，不指望维护者记得 |
| E02 | 统计区间的日期改为绑定参数；不绑定的只剩维护者片段、标识符与封闭枚举（分组粒度） | ADR-008 的"值一多就换绑定"在本切片兑现；ADR-009 取代 ADR-008 |
| E03 | 数据新鲜度 = 映射所在表的 `MAX(time_column)`，**确认后**与业务查询同一次执行里探测 | 确认前不跑任何 SQL 是 1A 的铁律（I2），所以提醒只能出现在结果上，不在确认单上——这是有意识的取舍，写进文档 |
| E04 | 新鲜度只说"库中最新一条记录的日期"，不说"数据完整到哪天" | 最新记录那天本身可能没导完；系统只知道前者 |
| E05 | 新增规则键 `group_by`（分组方式），只能来自用户：问题里的「每天/每周/每月/按渠道」或 `--group-by` | 与 `period` 同理：文档无法注入分组；分组改变了"一个数"还是"一张表"，是口径的一部分，进哈希 |
| E06 | 时间粒度是封闭枚举（天 / 周（周一起）/ 月），每种粒度每种方言各有一条维护在代码里的表达式；维度由维护者在映射文件里按表声明 | 粒度表达式与维度列都不来自用户，不需要绑定；三方言各自对照 Python 参照 |
| E07 | 「日均」「平均每天」不当分组处理，而是列为缺口 | 日均是另一个指标；把"每天"读成分组会算出一张表冒充平均数，读成不分组会算出总数冒充平均数 |
| E08 | 一次最多一个分组；两个不同分组（「每天各渠道」）列为缺口 | 多维交叉超出本切片；认不出就问，不猜 |
| E09 | 文档规则只能**选择**维护者声明的映射，不能**成为** SQL | 文档内容是数据（§3.2 的信任边界不变） |
| E10 | 对应关系是确定性的：维护者在每条映射上声明 `enforces: {规则键: [字眼]}`；已验证的逐字引文里出现某映射的字眼，即"这条文档规则与该映射对应" | 不让模型判断语义。字眼由维护者写、走 PR 评审；匹配是子串，可复现 |
| E11 | 引文同时命中两种取法（两组互不相交的字眼）→ 不对应、标为无法核对 | 「不按注册日期，按首单日期」同时含两种写法，子串匹配分不清，就不声称 |
| E12 | 文档依据一致指向唯一可执行口径时，草案直接带上该口径，标「文档依据」并带出处；用户仍需确认，`--variant` 可改 | 这是"文档规则进入 SQL"的唯一通道：经由维护者映射，而且摆在确认单上 |
| E13 | 采用某份文档的写法后，若它唯一对应一个口径，就不再单独问口径；同时给出矛盾的 `--variant` 直接拒绝 | 同一个人在同一条命令里说了两件互相矛盾的事，照哪个跑都是猜 |
| E14 | 结果行把"已由执行施加"的文档规则计入执行口径；不一致的规则单独点名，不再笼统免责 | 延续 v0.6/0.7 的原则：只声称执行了的，但也不再对查得出的不一致装作不知道 |

## 3. 对接方必读

- **Connector 协议**：`execute(sql, *, timeout_s, max_rows, params=())`，不新增其他成员；
  `sql` 中的 `?` 是占位符，`params` 是按位置的值元组。不传 `params` 时行为与 v0.7 完全一致
  （agent 的 `execute_sql` 工具路径不变）。
- **诚实说明**：SQLite 是引擎级绑定；PyMySQL 与 clickhouse-driver 是驱动在客户端转义后替换，
  不是服务端预编译。收益是值不再经过本项目的字符串拼接，而交给驱动的转义器——这是 DB-API
  的标准契约，不是更强的保证。
- `QueryRun` 新增 `params`（字符串元组）、`data_through`（ISO 日期，未知为空）与
  `freshness_sql`（执行过的探测语句，审计用；实施中补上）。存储自动补列，旧库可读。
- 新鲜度探测：结构化映射且有 `time_column` 时，执行 `SELECT MAX(time_column) FROM source`，
  与业务查询同一安全检查、同一执行器；探测失败不影响业务结果，结果上写"未能确定"。
- 分组规则值：`day` / `week` / `month` / `dim:<维度键>` / `none`（明确不分组）。
- 映射文件新增顶层 `dimensions:` 与条目级 `enforces:`：

  ```yaml
  dimensions:
    - key: channel
      label: 渠道
      aliases: [来源渠道]
      columns: {users: channel}      # 表 → 列；没有声明的表不能按它分组
  mappings:
    - metric: new_users
      variant: registered
      ...
      enforces:
        counting_basis: [created_at, 注册日期]
        filters: [internal_test]
  ```
- 规则与候选新增 `implies`（引文对应的口径键元组），仅在非空时进入内容哈希——旧草案的
  哈希不变。

## 6. 风险与回滚

- Connector 协议加的是带默认值的关键字参数，旧实现与测试替身不受影响；回滚点 `v0.7.0`。
- `%` 成对处理只在传参时生效；词法由 sqlparse 负责，字符串字面量里的 `%` 也成对（驱动的
  `%` 替换不认字面量），这正是要的效果。
- 新鲜度探测多一条查询：成本是一次 `MAX()`，演示库有时间列索引。没有索引的大表上它可能
  很慢——受同一超时约束，超时即"未能确定"，不影响业务结果。
- 字眼匹配是启发式：维护者写的字眼太宽（如"日期"）会让不相干的引文"对应"上。缓解：对应
  关系与字眼都显示在确认单上，由人判断；文档写明字眼应当互斥、具体。

## 7. 明确不承诺

多维交叉分组；日均等派生指标；按维度取值过滤（「抖音渠道的新增用户」，需要绑定用户给的
值，本切片的绑定机制为它铺路但不做）；数据完整性（只报最新记录日期）；跨表维度（需要
join）；文档规则的语义蕴含判断。

**实施中发现并改掉的**：旧 P10 测试的 2030 区间其实落在数据之后（新行为正确地改判为"还没
有数据"）；确认单上维度显示成键名（按 channel）；预选口径后仍写"需要你选一个"；结果行文档
规则的句号。

**发版前双轴 review（Standards / Spec）改掉的**：
- F9 只做了一半：没声明的维度词被静默丢弃、给出总数。现在「各城市的」「按城市分组」「每个
  用户的」这类明确说法会停下来问；更随意的说法仍认不出（写明的限制）。
- 分组词误判：「部分渠道」「部分月份」被当成分组，「区分日期」「按日期」被当成按天。
- 探测失败时空组被标成「无记录」——F5/F8 要防的正是这种混淆；现在标「未知」。「无记录」
  此前没有任何断言，补上。
- 分组查询整个区间在数据之后时，空结果措辞走错分支。
- F13 的拒绝只在 CLI 里：服务层现在拒绝同一次补充里"采用的写法"与"选定口径"矛盾；CLI
  测试改为数 runs 表证明未执行。
- E11 的判定改为"独有词"：{x, y} 对 {x} 归 x、y 独有的那一种，而非两者都算。
- 新写入的草案对 v0.7 读取器不兼容（候选里多了 `implies` 键）：改为只在非空时写入。
- 测试规范：`pytest.raises` 补 `match=`、模块注释前缀、两个测试名。

**设计上的代价，照实写**：新鲜度提醒只能出现在结果上，确认单上看不到——查一次最新日期也是
查询，而确认前不查询是 1A 的铁律。字眼对应的强度等于维护者词表的质量，演示映射里就踩到一次
（「扣除」同时出现在「不扣除退款」里）。
