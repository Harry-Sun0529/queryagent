# v0.5.0 后可靠性修复计划

基线：d00b6c7，2026-09-09。用户已授权修复核查项，要求先明确完整方案与验收，避免冗余防御代码。本轮不发布、不推送，不实施新 RAG/MCP/Web 功能。

## 1. 日志恢复

保留现有 ResultLog/read_trace 接口。逐条以 bytes 读取 JSONL，解码失败只影响该行；行数统计也读取 bytes。恢复后首次追加前，若原文件末尾没有换行则补一个换行，隔离坏尾行，不重写历史日志。真实续跑若签名缺失则拒绝，空签名仍允许只读检查旧日志。

验收 seam：ResultLog 的 append/completed、read_trace/count_trace_lines。用完整记录＋残缺 JSON／UTF-8 尾字节复现，确认旧记录仍在，续跑追加的新记录再次恢复仍在；正常中文不改变。只对已知解码／结构错误容错，I/O 错误继续暴露。不承诺断电持久化，只承诺进程中断后的完整行恢复。

## 2. 实验身份

抽出单一 run_signature 函数，CLI 只调用。指纹包含题目内容、有效 LLM 配置、执行上限、metrics 内容、运行代码指纹及数据库身份。本地 SQLite 使用文件内容哈希（含存在的 WAL）；公开集只对其数据库文件取指纹，不分析 test 题目。服务端数据库无可靠本地快照，新增可选 --data-version 由操作者声明，服务端续跑必须提供；不做自动数据库扫描。密码／API key 不入日志或指纹元信息。旧签名与新签名不兼容，显式拒绝混用。

验收 seam：签名函数及 CLI eval --resume。相同条件复用；同名不同内容题集、温度、metrics、数据库内容改变均拒绝。只改变输出路径、trace、并发度不改变评分身份；不同运行模式区分。服务端 snapshot token 的真实性由操作者负责。

## 3. 并发持久化与停止

保留单写者，使用有界在途 future（最多 concurrency 个）。按完成顺序消费并立即落盘，最后按题序输出报告。连续上游失败按完成顺序定义；触发停止后不再提交新题，收集已在途完成的可测结果并保存后退出。共享 ExitStack 仍只在 worker 结束后关闭资源。

验收 seam：CLI main(eval)，脚本化 backend＋真实临时 SQLite。用线程事件控制：首题阻塞，后题完成，首题放行前已经可以从日志恢复后题；熔断后不启动新任务，已完成测量保留；既有串并行报告一致测试保持通过。不依赖 sleep 进行竞态测试。

## 4. MySQL

超时设置失败向调用方抛 QueryError，不执行业务 SQL。连接配置显式 read/write timeout；服务端 execution timeout 与客户端等待限制分别说明，不能承诺客户端超时等同于服务端取消。连接池对获取失败／重连失败恢复容量记账，队列等待有上限。

业务查询使用 SSCursor，最多读取 max_rows+1 行以确定 truncated。截断时丢弃仍有未消费结果的连接，避免 cursor.close 排空全部结果；完整读完才复用连接。不修改 SQL 字符串、不加 SQL 重写框架。实现前验证驱动的 cursor 关闭行为，以最小适配处理剩余结果。

验收 seam：MySQLConnector.execute/get_schema/close；驱动是外部边界，可用受控替身模拟网络错误。覆盖超时设置拒绝后未执行查询、重连失败后下一请求可恢复、截断只读取上限且下一查询获得可用连接。能启动本地数据库则补真实只读／超时／截断验证；否则明确保留真机限制。读上限不等于扫描预算，新的总预算及全局并发策略仍属下一轮。

## 5. 评测语义

保留历史有价值的“任意 SQL 命中”作为 query-trajectory hit，不冒充最终自然语言答案正确。补充终止完成状态，在报告中区分异常终止与正常回答。首次 SQL 是否命中只由首次执行决定，后续失败不能追溯改变。结果被截断时不以截断前缀认定完整匹配。

不引入 LLM judge、字符串猜测或为自然语言答案强造评分；最终答案的语义正确性明确为未测量，下一轮结构化口径/答案才有可靠验收接口。报告标注评分版本，旧报告不改数字，README 主表明确为旧口径历史测量。

验收 seam：run_case/aggregate/render_report。首条正确后续报错仍算首次命中；SQL 命中后 ErrorEvent 记录为未完成；错误自然语言答案不能被报告宣称为“最终答案正确”；截断结果不算完整命中。保留验证性 SQL 场景。

## 6. 文档与真实串并行对照

更新 README/eval 文档中的旧数量、key 说明、全追问零分错误、统计功效与因果过度归因；保持历史报告和已发布版本数字。T26 保留为未完成真机验证，删除不等工作量的加速结论。提供可执行对照方案：同代码、同数据版本和模型条件，交替串行/并行多次运行，报告完成数、拒绝/限流、耗时与逐题差异；不把一次接近结果称为等价证明。

若当前环境无可用凭据，不取用历史附件密钥、不捏造测量。真实对照记录明确外部依赖。现有公开 API 不新增兼容性承诺，保持本轮接口改动最小。

## 执行与验证纪律

按以上顺序，一个故障行为先写失败测试，再实现最小修复。不先写全套假想测试、不增加通用策略层或重复异常包装。最终运行 ruff、mypy、pytest、git diff --check，并检查新增代码复杂度及文档一致性。验证结果与未完成外部验证附在本文末尾。
