# v1.0.0：接入、评测、冻结、答辩

日期：2026-09-11。状态：计划（验收标准在实现前固定）。承接 v0.9.0（切片 1D/1E）。

交接文档的三个阶段是核心 CLI 闭环 → MCP/Web → 场景评测及答辩。v0.9.0 完成阶段 1；本版本做
阶段 2 的最小形态和阶段 3。

## 1. 为什么做这一刀

1. **别的 Agent 用不了它。** 现在只有 CLI。MCP 能让 Claude Code 这类宿主直接调用，但宿主里的
   Agent 自己就能「点确认」。产品的价值全在确认门上，所以 MCP 必须做成：Agent 能准备、能执行，
   不能确认。
2. **价值没有被度量。** 现有评测只量 Text-to-SQL 准确率，不量本产品要保证的东西：该问的有没有
   问、数字对不对得上、有没有未经确认就执行、有没有越权。
3. **接口没有冻结，也没有发布。** PyPI 从 v0.1 起一直没发；`queryagent` 这个名字 2026-09-11 查询
   返回 404，尚未被占用。
4. **讲不清调用链。** 交接文档写着「用户还不能独立讲清核心调用链」「不把功能堆叠当作简历合格
   标准」。

## 2. 已定的设计取舍

| 编号 | 取舍 | 理由 |
|---|---|---|
| P01 | MCP 只是 `QueryWorkflow` 之上的又一个协议适配器，不复制规则。手写 stdio JSON-RPC，零新依赖，固定一个协议版本，只实现 `initialize` / `tools/list` / `tools/call` / `ping`。同时把 CLI 里组装 workflow 的代码抽成 `workflow/wiring.py::build_workflow(config)`，CLI、MCP、Web 共用 | `service.py` 开头：一处检查存在两份，迟早只剩一份。手写与手写 httpx 的 OpenAI 后端同理，也更讲得清协议 |
| P02 | 身份来自启动 MCP 服务的人（`queryagent mcp --subject --workspace`，写在宿主配置里）；工具参数里没有身份字段 | D11：模型给出的 subject 只是字符串，不是授权 |
| P03 | MCP 不暴露确认。工具只有 `list_metrics` / `prepare_query` / `amend_query` / `query_status` / `execute_query`；`execute_query` 只收 `draft_id`，由服务端找当前版本上由人产生的确认（新增 `QueryWorkflow.execute_confirmed`） | 在工具表这一层就无法表达「Agent 替人确认」 |
| P04 | 确认只在人的通道产生：本地确认页（`queryagent web`）或终端 `queryagent confirm <draft_id>`。确认记录新增 `channel`（cli / web），不存在 mcp 这个值 | 便于审计；砍掉 Web 页时终端命令就是退路 |
| P05 | Agent 代填的规则用新来源 `RuleSource.AGENT`（「Agent 代填」），进哈希；确认页高亮、人可以改；结果上写「X 由 Agent 代填、经你确认」 | Agent 猜的值既不是文档也不是用户本次约定，标成「本次约定」正是 D07 要防的混淆 |
| P06 | 确认页：标准库 `http.server`，只监听 127.0.0.1；启动时打印一次性登录链接（随机令牌），浏览器拿 HttpOnly + SameSite=Strict 会话 cookie；每次 POST 校验 Host（防 DNS rebinding）、Origin、绑定草案版本与哈希的表单令牌；所有输出 `html.escape`；不做聊天界面、不引 JS 框架 | 本地网页服务的三类典型漏洞：CSRF、DNS rebinding、XSS；文档引文是不可信文本 |
| P07 | 诚实边界：同一 OS 用户下拥有任意 shell 的 Agent，技术上能绕过任何本地确认。本设计防的是「Agent 经工具协议替人确认」与「别的网站替人确认」，不防「Agent 攻破本机」；多用户部署需要真正的 Web 身份认证，不在 1.0 | 写进 SECURITY；答辩时必须能主动说出 |
| P08 | 场景评测量「该问必问、数字对得上、未确认执行为 0」。确定性场景进 pytest / CI；涉及文档抽取的用 DeepSeek 跑 3 次报区间 | DeepSeek 无 seed，单次跑分是噪声 |
| P09 | 数字对照用独立参照：同一数据的另一种算法（Python 逐行重算，或各方言另一套原生函数），不是把被测 SQL 再跑一遍 | 自己对照自己永远一致 |
| P10 | 越权与注入用金丝雀串：finance 文档里放唯一标记，断言它不出现在 ops 身份的任何输出、确认单、送给模型的 prompt、trace 里 | 把「没泄露」变成可以数的数 |
| P11 | 基准重跑：1.0 代码上自建 36 条跑 3 次、BIRD dev100 跑 1 次；封存 test200 在接口冻结后跑一次作为 1.0 的数字，之后不因它改任何东西；只有 DeepSeek 一组数，照实写 | ADR-004 与 eval/README 的纪律：不因测试结果改系统 |
| P12 | 1.0 公开契约：CLI 命令与参数、`config.yaml` 结构、`metrics.yaml` / `query_mappings.yaml` 格式、退出码、`queryagent.__all__`（新增 workflow 对外类型）、MCP 工具名与参数 schema、状态文件向前兼容（1.x 能读 0.6 起写下的状态）。契约快照测试钉住 | 语义化版本号从 1.0 起才真正有约束力 |
| P13 | 冻结前先列破坏性改名清单，只改确有歧义的名字 | 1.0 前改是免费的，之后要走弃用 |
| P14 | 先在 TestPyPI 演练，再用 GitHub Actions 可信发布（OIDC，仓库里不放 token）。PyPI 账号与 pending publisher 由维护者本人设置，正式上传前单独确认 | 同一版本号上传后不能重传；对外发布 |
| P15 | 答辩材料以真实代码为锚：flow 调用链讲解（每一跳 `file:line` 与为什么）、设计取舍问答库（锚到 ADR）、3 分钟演示脚本；用两轮模拟面试检验，完成标准不是「文档写完」 | 交接文档的原话 |

## 3. 对接方必读

- 宿主配置（Claude Code / Claude Desktop 通用）：

  ```json
  {"mcpServers": {"queryagent": {"command": "queryagent",
    "args": ["mcp", "--config", "/abs/config.yaml", "--subject", "alice", "--workspace", "ops"]}}}
  ```

- 工具：

  | 工具 | 说明 |
  |---|---|
  | `list_metrics()` | 可用指标与口径 |
  | `prepare_query(question)` | `{draft_id, version, status, sheet, rules[], missing[], candidates[], confirm_hint}` |
  | `amend_query(draft_id, expected_version, rules?, adopt?, variant?, period?, group_by?, filter?)` | 以 `AGENT` 来源写入 |
  | `query_status(draft_id)` | `needs_input` / `awaiting_confirmation` / `confirmed` / `expired` / `executed` |
  | `execute_query(draft_id, idempotency_key)` | 行、列、覆盖说明、SQL 与参数；没有人的确认时返回 `isError`，不跑 SQL |

- 确认通道：`queryagent web --config … --subject … --workspace … [--port 8765]`（待确认列表、
  草案页、`POST /drafts/<id>/amend`、`POST /drafts/<id>/confirm`）；终端 `queryagent drafts`、
  `queryagent confirm <draft_id>`。
- 库接口：`from queryagent import QueryWorkflow, ActorContext, …`，给嵌入方用。
- MCP 服务的 stdout 只放协议帧；日志与提示全部走 stderr。

## 5. 不变量与验收

| 编号 | 不变量 |
|---|---|
| H1 | MCP 工具表里没有确认；任意 MCP 调用序列都产生不了确认记录（性质测试） |
| H2 | MCP 调用的身份只来自启动参数；工具参数里的 subject / workspace 字样被忽略 |
| H3 | 没有人的确认时 `execute_query` 失败且零 SQL；人确认后同一草案执行一次（幂等） |
| H4 | Agent 代填的规则显示为「Agent 代填」并进哈希；绝不显示为「本次约定」或「文档依据」 |
| H5 | MCP 的 stdout 只有协议帧 |
| H6 | 确认页：Host 不是 127.0.0.1、CSRF 令牌缺失或错误、跨站 Origin、没有会话 → 拒绝且状态不变 |
| H7 | 确认页上所有文档与用户文本都经转义 |
| H8 | 确认页提交渲染时的版本与哈希；期间草案改版 → 拒绝，不确认新版本 |
| H9 | 确认记录带通道（cli / web） |
| H10 | 场景评测：未确认执行数 = 0、跨空间泄露 = 0、注入生效 = 0。硬门槛，任一非零不发版 |
| H11 | 场景评测的数字对照全部来自独立参照 |
| H12 | 改动任一冻结面却不更新快照与 CHANGELOG → CI 失败 |
| H13 | wheel 在干净 venv 安装后 `queryagent --help` 与 SQLite 演示 flow 可跑；不含示例凭据 |
| H14 | 0.6–0.9 写下的 workflow.db / knowledge.db 在 1.0 可读 |
| H15 | 讲解文档的 `file:line` 锚点对得上 1.0 代码（脚本检查） |

## 7. 风险与回滚

- 回滚点 `v0.9.0`。MCP 与 Web 是新增入口；服务层只增加 `execute_confirmed`、`channel` 与 `AGENT`。
- MCP 协议演进：固定协议版本；发版前用真实宿主（Claude Code）走一遍；帧测试取自规范示例。
- 本地网页安全：H6 / H7 逐条测试；只绑定 127.0.0.1，没有远程模式。
- 评测不确定性：模型相关场景跑 3 次报区间；H10 是结构性质，与模型好坏无关，必须恒为 0。
- PyPI 不可逆：先 TestPyPI；1.0.0 只上传一次；上传前维护者本人确认。
- 冻结太早：先做 P13 的改名清单。

## 8. 明确不承诺

Web 聊天界面；多用户网页身份认证或 SSO；远程 MCP（HTTP 传输）；多副本部署；强模型的数字；
PostgreSQL 连接器；按人的文档权限；企业知识库连接器；OCR。

## 9. 真机验证

- MCP：Claude Code 里 `claude mcp add …` 后问「上个月新增用户多少」——Agent 调 `prepare_query`，
  执行失败并请人去确认页；人在浏览器确认后 Agent 执行，得到 5812。让 Agent「替我确认」：没有
  这样的工具，确认表为空。
- 确认页：浏览器手测；curl 做负面测试（伪造 Host、缺令牌、跨站 Origin、含 `<script>` 的文档）。
- 场景评测跑一次，H10 三项为 0，报告落盘。
- 干净 venv 装 wheel 冒烟，再从 TestPyPI 装一遍；锚点检查脚本通过。
