# ADR-014: What 1.0 promises to keep, and how a change to it is caught

Status: accepted · Date: 2026-09-11

## Decision

From 1.0 the version number means something: a release that breaks any of
the following is a major release.

| surface | what is frozen | snapshot |
|---|---|---|
| CLI | every command, positional argument and flag, its choices and literal defaults | `tests/contract/cli.json` |
| exit codes | 0 done · 2 refused, declined or misconfigured · 3 eval cases failed · 70 our defect · 75 retry later · 130 interrupted | `tests/contract/exit_codes.json` |
| `config.yaml` | every section and key | `tests/contract/config.json` |
| `metrics.yaml`, `query_mappings.yaml` | every key a maintainer may write | `tests/contract/files.json` |
| library | `queryagent.__all__` | `tests/contract/public_api.json` |
| MCP | tool names and input schemas | `tests/contract/mcp_tools.json` |
| state files | 1.x reads `workflow.db` written since 0.6 and `knowledge.db` since 0.7 | `tests/fixtures/state/` (written by those releases' own code) |

**Not frozen:** the wording of sheets, results and messages; modules and
names outside `__all__`; the confirmation page's routes and markup; eval
report formats; trace files. They change when they need to.

**How a change is caught.**

- `tests/test_public_contract.py` regenerates each snapshot from the code and
  compares it with the committed file.
- A surface that changed without its snapshot fails the test and shows the
  difference.
- Updating the snapshot is not enough on its own. The test also requires the
  newest section of `CHANGELOG.md` to carry the digest of all snapshots
  (`契约摘要：<12 hex>`). Changing a frozen surface therefore also means
  writing down, where users read it, that it changed.

**Compatibility policy.**

- **Additions** (a new flag, key, tool or `__all__` name) are minor releases.
- **Removing or renaming** a frozen name is a major release, and it goes
  through deprecation first:
  - for at least one minor release the old name keeps working and warns on
    stderr;
  - the CHANGELOG entry says what replaces it.
- **State files only migrate forward**, in place, by adding columns with
  defaults that say what older rows were. A newer state file is not promised
  to open in an older release: 0.9 cannot read a draft containing
  「Agent 代填」.

## Renames reviewed before freezing (P13)

Renaming was free until now, so every frozen name was read once for
ambiguity. None was renamed. The candidates considered:

- **`query_status`**: breaks the tools' verb-object pattern. Kept, because it
  reads as what it returns, and a rename would buy consistency at the price
  of a less obvious name.
- **`flow --filter` / `amend_query.filter`**: could be confused with the
  handbook rule key `filters`. Kept, because the help text and the sheet
  label (「取值过滤」 vs 「过滤条件」) keep the two apart. The rule key
  `filters` is document vocabulary and is not a CLI or MCP name.
- **`workflow.freshness_before_confirm`**: long, but says exactly when it
  applies.
- **`budget.max_queries_per_day`**: counts statements, not questions. The
  docstring and README say so; `max_statements_per_day` would be more exact
  but less recognisable, and 0.9 shipped the name.

## Context

Before 1.0 every surface could change between minor releases, and several
did: the mapping format gained structure (0.7), dimensions (0.8) and values
(0.9). A library used by other agents through MCP needs names it can rely
on, and the first thing that breaks that reliance is an accidental rename
nobody noticed.

## Consequences

- (+) An accidental change to a frozen surface cannot pass CI, and an
  intended one cannot ship without a CHANGELOG line.
- (+) Old state files written by the real old code are kept as fixtures, so
  "1.x reads 0.6" is tested, not asserted.
- (−) Every intentional change to a flag or key now takes three edits: the
  code, the snapshot and the CHANGELOG. That cost is the point.
- (−) Wording is deliberately unfrozen, so a script parsing sheet text can
  break in a minor release. The structured MCP output is the interface for
  programs.
