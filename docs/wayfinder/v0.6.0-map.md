# v0.6.0 — 让「文档依据」这一档第一次真的成立

## Destination

一个 v0.6.0 tag，使 `queryagent flow` 的口径确认单上**第一次出现带出处的
「文档依据」**：规则引用到具体文档的具体位置，两份互相矛盾的文档各自带着
出处并列，文档没说清楚的规则显式列为缺失。权限在检索前生效，引用由服务端
验证，撤权与文档变更使旧确认失效。

完整方案见 [切片 1B 技术方案](../specs/workflow-slice-1b-2026-09.md)。

## Notes

- **本 effort 把 execution 纳入 map**（沿用 v0.3.0–v0.5.0 的做法，覆盖
  plan-don't-do 默认值）。
- 遵循 skills：`tdd`（预声明 seam、红→绿、一次一个纵切）、`code-review`。
- **铁基线**：345 passed / 1 skipped 全绿；`tests/test_metrics.py` 在分词器
  提取后行为不变。任一回退即回滚。回退点是 `v0.5.1`，它已过远端 CI。
- **本轮的指导教训**（来自 1A 的压测复盘）：**能从数据流上消灭的失败模式，
  不要留给校验去挡**。模型返回下标而不是引用字符串，坏引用就从"需要检测的
  攻击"变成"无法表达的状态"。
- 诚实边界：引用的存在性与逐字性可确定性证明；**语义支持不可证明**，只做
  粗筛并把原文摆到确认单上交给人判。不得在 README 写成"保证引用支持规则"。
- 唯一可用对话模型：DeepSeek。**DeepSeek 没有 embeddings 端点**（已核实
  官方文档），语义检索需第二把 key；前三张票都不需要它。

## Decisions so far

<!-- one line per closed ticket -->

- [T28 — 本地索引与授权检索](tickets/28-authorized-retrieval.md) — 权限做进
  Protocol 的形状：每个方法都收 scope，没有不带 scope 的重载，"取回再过滤"
  写不出来。撤权与删除共用一条消息。引用的内容哈希带在对象上但不进渲染串。
- [T29 — amend 允许伪造「文档依据」来源](tickets/29-amend-source-forgery.md) —
  约束属于「amend 这个动作」而非「Rule 这个类型」：DOC 规则本身合法（抽取管线
  正要产出），不合法的是调用方在一次补充里自称文档依据。
- [T27 — 文档导入与切片](tickets/27-document-loading.md) — 切片边界跟章节走
  而非 token 数（横跨规则边界的切片让引用无法解析）；归一化按"两侧是否都为
  中日韩字符"决定删不删空格；标题用冒号而非空白与正文分隔，否则会造出文档里
  不存在的子串。DOCX 用 stdlib 解析，PDF 走 `[docs]` extra。
