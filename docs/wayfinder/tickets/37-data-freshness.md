# T37 — 结果说得出库中最新记录是哪天

## Question

演示数据止于 2026-08-22。9 月问「上个月」只算到 22 日却当整月报，问「本月」得到空结果
却说不出原因。"没有数据"和"业务为 0"必须分开。

## Work

- 结构化映射有 `time_column` 时，确认后的同一次执行里探测 `MAX(time_column)`；记入
  `QueryRun.data_through`。探测失败不影响业务结果，结果上写"未能确定"。
- 结果：区间末尾超出最新记录 → 写明缺了哪几天、只覆盖到哪天；整个区间都在其后 → 空结果
  解释为没有数据；没有区间 → 写"全部数据（库中最新记录：…）"。

## Done when

- F4–F6，真机：「上个月新增用户」写明只覆盖到 08-22；「本月成交额」说明整个区间都没有数据。

## Resolution（2026-09-11）

- 探测是映射所在表整张表的 `MAX(time_column)`，不带映射的 `where`：问的是数据到哪天，
  不是这个指标筛出来的行到哪天。整条 `sql:` 映射没有时间列可读，不探测、也不声称。
- 在确认、证据复查、幂等占位都通过之后才探测，与业务查询同一执行器、同一安全检查——所以
  确认单上无法提前提醒"不完整月"，这是 I2 的代价，写在方案里。探测失败只丢说明，不丢数字。
- 措辞只说"库中最新一条记录在哪天"，并提醒那天本身可能没导完；区间整个在数据之后时，空
  结果说"还没有数据"，COUNT 的 0 旁边也会说明它不代表业务为 0。
- 旧的 P10 CLI 测试用的是 2030 年区间——它其实落在数据之后，新行为把它正确地改判为"还没有
  数据"；P10 本身改用数据范围内的空区间来测，另加一条专测数据之后的情形。
- 三方言：MySQL / ClickHouse 返回 `datetime`、SQLite 返回文本，都解析为与 `DATE()` /
  `toDate()` / `date()` 相同的日期（集成与端到端测试）。真机两问与 Done when 一致。
