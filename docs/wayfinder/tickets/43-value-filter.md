# T43 — 按维度取值过滤（可砍）

## Question

「上个月广告渠道的新增用户」只能分组，不能过滤。v0.8 的参数绑定为它铺好了路，但绑定只防得住
注入，防不住「一个不存在的值查出 0，冒充业务为 0」。

## Work

- 维度声明封闭取值 `values: {ads: [广告, 付费投放]}`。
- 规则键 `filter`（`dim:channel=ads`），只来自用户（问题字样或 `--filter`），进哈希；文档抽取
  的允许键不变。
- 识别要求维度语境（「X渠道」「渠道为X」），避免「广告费」这类误判；认不出的取值列为缺口并
  给出可选值；一次一个维度。
- 编译为 `AND (col = ?)` 绑定参数；新鲜度探测仍查整表。

## Done when

- G17–G18；真机：「上个月广告渠道的新增用户」= 2307，与按渠道分组的 ads 一致；加「每天」后逐日
  合计等于 2307；三方言对照。

## Resolution（2026-09-11）

- 取值是维护者在维度上声明的封闭集合：`values: {ads: [广告, 付费投放]}`；一个说法只能指一个取值，
  否则加载时拒绝。没有 `values` 的维度不能过滤。
- 规则键 `filter`（`dim:channel=ads` 或 `none`），只能来自用户（问题字样或 `--filter`），进哈希、
  编译为 `AND channel = ?`，值作为参数绑定，顺序排在区间日期之后。文档抽取的允许键不含它。
- 识别两种说法：取值在前（「广告渠道」）、在后（「渠道为广告」）。停下来问的三种：没声明的取值
  （「抖音渠道」「渠道为抖音」，列出可选取值）、同时多个取值（「广告和推荐渠道」）、两个维度同时
  过滤。不当成过滤的：「各渠道」「按来源渠道」（那是分组）、「渠道分布」「渠道占比」（问的是全部
  取值）、「广告费」「推荐语」（别的词）、指标名紧挨维度名（「新增用户渠道」）。
- 编译器拒绝而不是丢掉：表上没声明该维度、规则里的取值不在声明里、整条 `sql:` 映射，都拒绝。
  分组与过滤共用「这个维度在这张表上有没有声明」的判断，不再各写一份。
- 历史沿用不记忆过滤条件——它和区间、分组一样描述的是这一次的问题。
- 真机（SQLite 演示库）：「上个月广告渠道的新增用户」= 2307，与按渠道分组的 ads 一致；「上个月
  每天广告渠道的新增用户」22 天有记录、合计 2307；「抖音渠道」停在追问处，退出码 2，提示列出三个
  可选取值。MySQL / ClickHouse 集成测试把绑定的取值与手写的 `channel = 'ads'` 对照，单独与按天
  两种形态都一致。
- **实施中发现**：认没声明的取值时，正则从句首起算，把「上个月各渠道」读成取值「上个月各」，
  端到端测试里「各渠道」因此多出一个过滤缺口。改为候选词不得含断词字（的、月、天……、各、按、
  每），只能从它们之后开始。
- 写明的限制：识别是启发式——没声明的取值只在「独立成词 + 维度名」的形态下被发现，更随意的说法
  可能认不出；过滤条件显示在确认单上，由人确认。
