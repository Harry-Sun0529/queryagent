## Resolution (closed 2026-08-19)

分析见 [eval/results/dual-model-analysis.md](../../../eval/results/dual-model-analysis.md)。
各跑 3 次的核心结论：

- **强模型赢在「一次写对」，不赢在「最终答对」**：首次通过率
  61-72% → 78-83%，但自修正后两者收敛（94-100% vs 89-100%）。
  这是架构贡献与模型贡献的分界线：**自修正闭环用 1/3 的成本把弱模型的
  最终正确率拉到了强模型水平**，代价是多一轮工具调用。
- **追问判断与模型强弱无关**（两模型三跑全 4/4）——它由系统提示的三步
  协议 + 条件注入决定，是提示工程的产物。若它随模型波动，反而说明触发
  准则写得不够硬。
- 口径标注是强模型唯一稳定占优处（3-4/4 vs 2-3/4）：弱模型常「用对了
  定义但漏了声明」，属表述要求而非正确性。
- pro 贵 2.7x、慢 50%，但每题 token 更少（少绕路）——成本差完全来自单价。
- 缓存命中 86-90%：系统提示在多轮间不变被 prefix cache 命中，命中价便宜
  约 30 倍。若 context 前缀不稳定，这个杠杆会立刻消失。

对本项目目标用户（交互式取数），**flash + 自修正是更划算的默认**。
