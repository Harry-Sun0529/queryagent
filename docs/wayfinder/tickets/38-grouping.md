# T38 — 按天 / 周 / 月或维护者声明的维度分组

## Question

「上个月每天的新增用户」「各渠道的新增用户」现在只得到一个总数，而且系统不说它丢了
"每天"两个字。

## Work

- 规则键 `group_by`，只能来自用户（问题里的字样或 `--group-by`）；「日均」、两个不同分组
  列为缺口。
- 映射文件顶层 `dimensions:` 按表声明维度列；时间粒度的三方言表达式维护在代码里。
- 编译为 `GROUP BY`；结果按区间补齐每一组，区分"无记录"与"无数据"。

## Done when

- F7–F10；三方言逐组与 Python 参照一致；真机「上个月每天的新增用户」31 行、22 日之后标
  无数据。

## Resolution（2026-09-11）

- 解析是封闭集合：每天 / 每周 / 每月与维护者声明的维度词。「日均」「每小时」与两种不同分组
  抛错、列为缺口——日均读成每天是一张表冒充平均数，读成不分组是总数冒充平均数。**没有声明
  的维度词不被识别**：系统无从知道「按渠道」是一个分组请求，这是写明的限制。
- 维度按表声明在映射文件（列名是 SQL，走维护者评审）；映射读的表没有该维度就拒绝，不替人
  join。
- 粒度表达式三方言各一条，分组键统一为组的第一天；GROUP BY 重复表达式本身，是三种方言在
  严格分组下都接受的唯一写法。对照用各方言**另一套**原生函数：MySQL `DATE_FORMAT` /
  `YEARWEEK(…, 3)`，ClickHouse `toYYYYMMDD` / `toYearWeek(…, 3)` / `toYYYYMM`，逐组一致。
- 结果按区间补齐每一组：区间内缺的是「无记录」，最新记录之后是「无数据」；首尾不完整的周 /
  月明说。截断的结果不补齐，否则会把被截掉的尾部标成空。
- 真机：按天 31 行，08-23 起 9 行无数据；按渠道 ads 2307 / organic 3083 / referral 422，
  按周 510 / 1903 / 1894 / 1505，两种拆法合计都是 5812，与不分组的总数一致；「日均」停下
  来问，未执行任何查询。
- **实施中改掉的**：确认单上维度显示成键名「按 channel」，不是业务人员能复述的话（D04）；
  改为维护者声明的中文名。
