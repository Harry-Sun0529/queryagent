# T42 — 沿用上次确认过的选择

## Question

alice 昨天选了首单口径，今天再问同一个指标还要重选一遍。交接文档要求可复用历史选择，但它
不是团队标准。怎样沿用而不让历史悄悄盖过文档、也不让脚本静默沿用？

## Work

- 新来源 `RuleSource.HISTORY`（「历史选择」），写明来自哪天的哪次执行，进哈希。
- `HistoryDraftBuilder` 包在 `CompositeDraftBuilder` 外，只填仍缺的键：口径、文档分歧里采用的
  写法、用户补过的缺口；不沿用区间与分组；不覆盖文档依据，不一致时点名。
- 由存储派生（drafts ⋈ confirmations ⋈ runs，成功执行过的），不另建历史表；run 记录映射指纹。
- 失效：映射指纹变化、所引文档复查不 OK、选项已不存在、超过 `history_max_age_days`；因文档
  失效不沿用时不说是哪份。
- `--yes` 不预填；`--no-history` 显式关闭。ADR-012。

## Done when

- G12–G16；真机：alice 再问时确认单显示「历史选择」与日期；bob、finance 空间看不到；改映射后
  不再沿用；`--yes` 不预填。

## Resolution（2026-09-11）

- 新来源 `RuleSource.HISTORY`（「历史选择」）：确认单上写明「沿用你 2026-09-10 确认过的选择」，
  并进哈希——沿用与重新选是两次不同的行为。构造时不带说明直接拒绝。
- 由存储派生，不另建历史表：同一人、同一业务空间、同一指标，最近一次确认过、执行成功、确认后
  没再改版的草案。
- 只沿用本人做过的选择（本次约定或历史选择）：
  - 口径：今天仍是可选项才沿用；
  - 采用过的文档写法：今天仍有同一出处的同一写法，且文档对此人仍然可见；
  - 自己补写的缺口：文档还没开始对它有分歧。
  区间与分组不沿用；文档依据和系统映射给出的规则由本次草案自己给。
- 只填缺口：文档依据已选定另一口径时不覆盖，确认单多一行「上次的选择：首单口径（你 2026-09-10
  确认过；与本次的文档依据不同，未沿用）」。
- 失效条件：映射指纹变化（run 上新记录的 `mapping_fingerprint`）、选项已不在、所引文档复查不通过、
  超过 `history_max_age_days`。v0.8 的 run 没有指纹，一律不沿用。失效不解释，不点名文档。
- 通道：`--yes` 不预填（没人看单），`--no-history` 显式关闭；在装配时决定，服务协议不变。
- 真机（SQLite 演示库）：
  - alice 选首单口径跑一次后再交互式提问：确认单显示「历史选择」，执行得 3559（与 v0.8 首单口径
    数字一致）；
  - bob、alice 在 finance 空间、首单映射多加一个 where 之后、带 `--yes`：四种情况都没有预填，都在
    选口径处取消（退出码 2），runs 表只有 2 条。
