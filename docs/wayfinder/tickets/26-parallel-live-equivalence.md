# T26 — 并行 eval 的真机准确率等价性（阻塞于账户余额）

## Question
[T24](24-parallel-eval.md) 的实现有测试层面的等价性保证（同一批 scripted
事件下并行与串行报告逐行相同），但**真机验证没做成**：那次 dev 100 题的
运行中途 DeepSeek 余额耗尽，64 个用例返回 HTTP 402，结果不可用。

耗时收益已验证（3 分 29 秒 vs 串行 22 分钟）；缺的是**准确率不受并发影响**
这一条在真实模型下的证据。并发下的限流与重试时序与串行不同，理论上可能
改变结果，这正是需要真机数据的原因。

## Work（账户充值后）
1. dev 100 题跑一次 `--concurrency 1`，再跑一次 `--concurrency 4`；
2. 比较两份报告的通过率与逐条结果，差异应落在无 seed 模型的正常噪声内；
3. 若并行明显更差，查限流/重试时序，必要时下调默认并发或加节流。

## Done when
- 两次运行的数字可比，结论写进 `eval/results/`；README 的并发建议基于
  这份数据而不是推测。
