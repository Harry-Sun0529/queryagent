# T26 — 并行 eval 的真机对照（不作等价证明）

## Question
[T24](24-parallel-eval.md) 的实现有测试层面的等价性保证（同一批 scripted
事件下并行与串行报告逐行相同），但**真机验证没做成**：那次 dev 100 题的
运行中途 DeepSeek 余额耗尽，64 个用例返回 HTTP 402，结果不可用。

此前 3 分 29 秒与串行 22 分钟并非同等成功工作量，不能认定耗时收益已验证。
同时缺少准确率和完成率在真实模型下的对照证据。并发下的限流与重试时序与串行不同，理论上可能
改变结果，这正是需要真机数据的原因。

## Work（2026-09-09 修订）
1. 相同代码、数据、显式模型与温度下，以 S/P/P/S 顺序执行 dev100；S=1、P=4。
2. 记录每轮完成数量、未测量/拒绝、SQL命中、正常完成、耗时、token与成本。
3. 比较逐题翻转和串行自身波动；报告观测差异，不将有限重复视为等价证明。
4. 若出现拒绝/余额耗尽，停止，不将该轮计作同工作量性能比较。

## Done when
- 四轮运行的数字可比，结论写进 `eval/results/`；README 的并发建议基于
  这份数据而不是推测。

## Resolution（2026-09-09）

四轮各100题完整完成、无缺测、签名相同、源码未变。串行SQL命中43/44，
并行43/47；完整墙钟平均之比2.73×。重复运行均有逐题翻转，未证明统计等价。
票据按修订后的“收集可比真机证据”目标完成，不按原标题宣称准确率等价。
完整证据见 [对照报告](../../../eval/results/reliability-2026-09-09-rerun/README.md)。
默认并发维持1，本地离线评测可选择4，不据此提高企业数据库资源上限。
