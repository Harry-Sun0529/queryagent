# T32 — 时间表述解析

## Question

问题里的「上个月」要变成一个人能核对、SQL 能用的绝对区间。怎样解析才既不猜、
又能覆盖取数里最常见的说法？

## Work

- `workflow/periods.py`：`Period(start, end)`（含首尾）、规范串编解码、
  `find_period(question, today)`、`parse_period(text, today)`。
- 封闭集合见方案 §4；多个不同区间或不可能的日期抛 `PeriodError`，调用方当缺口处理。

## Seams (tdd, 先红后绿)

1. `find_period` 2. `parse_period` 3. `Period.encode / decode`

## Done when

- 固定"今天"下覆盖方案 §4 每一行；跨年（1 月问上个月）、闰年二月、周一起算。
- 同一区间的两种说法（「上个月（2026年8月）」）不算歧义；两个不同区间算歧义。

## Resolution（2026-09-10）

`workflow/periods.py`：`Period`（含首尾、规范串编解码、`end_exclusive`）、
`find_period`、`parse_period`。42 条测试，固定"今天"为 2026-09-10（周四），覆盖方案 §4
每一行，外加跨年（1 月问上个月）、闰年二月、今天恰为周一时的"上周"。

关键决定：

- **认不出就返回 None，不是全量。** 调用方据此决定是否列为缺口；解析器自己从不
  替用户选"全部时间"。
- **不可能的日期（2026-02-30）抛错而不是跳过。** 跳过会让一个写错的日期悄悄变成
  不限区间的查询——比报错糟得多。
- **两个不同区间抛错，同一区间说两遍不算歧义。** 「上个月（2026年8月）」是一个区间；
  「上个月和本月」是本切片跑不了的对比，猜其中一个就是给错数字。
- 「本月」「本周」「今年」截至今天，「近N天」含今天，裸「8月」取最近一个不在未来的
  8 月——都是口径选择，确认单上以绝对日期展示，由人确认。
- 「目前天气」里含「前天」，用否定后顾排除；这类误识别的兜底是确认单上的绝对日期。
