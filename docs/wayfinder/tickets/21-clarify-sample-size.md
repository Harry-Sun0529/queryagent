# T21 — 把追问与口径标注补到能说话的样本量

## Question
追问行为、口径标注各只有 **4 条**用例。「4/4，三跑全对」听起来漂亮，
但 n=4 时它几乎不构成证据——这是当前所有数字里统计上最弱的一处，而追问
恰恰是本项目的差异化卖点。

## Work
自建集扩充：追问类（该问）与对照类（不该问）各 ~8 条，口径标注 ~8 条，
覆盖更多口径与更多歧义形态（时间口径、状态口径、聚合口径）。
新用例必须钉死输出契约（前几轮的教训）。

## Seams (tdd)
`load_cases` 对新用例的结构校验；用例的参考 SQL 逐条对 demo 库执行验证。

## Done when
- 追问相关用例 ≥16 条、口径类 ≥8 条；全部参考 SQL 可执行；
- 跑 3 轮取区间，README 用新分母重述这两个指标。

## Resolution (closed 2026-08-22)

- 四个口径补 caution（aov 按订单 vs 按用户、退款率按单数 vs 按金额、
  复购率全期 vs 固定窗口、活跃买家仅已支付 vs 含未支付），让歧义有多种
  形态而不是只有一种。
- 用例：clarify 2→8、no_clarify 2→8、metric 4→8，总计 20→36。
- **连带修正**：给 aov 加 caution 后，「我们的客单价是多少？」变成了真正
  的歧义问题——既有用例改为消歧版本，歧义版本转为 clarify 用例。
  一个口径获得 caution，就改变了「什么才是正确行为」，用例必须跟着动。
- 全部参考 SQL 逐条验证：过安全门、可执行、非空。
- 用例配比测试改为**按类下限 + 写明理由**，不再是「总数 == 20」这种
  什么也没说明的魔数。

**三轮结果（新分母）**：首次 20-23/28、自修正后 26-27/28、口径 6-8/8、
**追问 15-16/16**。追问在分母翻两番后依然守住——这才是能拿出去说的数字。
