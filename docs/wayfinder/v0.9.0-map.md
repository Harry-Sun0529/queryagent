# v0.9.0 — 有上限、能提前说新鲜度、记得你上次的选择、能按取值过滤

## Destination

一个 v0.9.0 tag，使 `queryagent flow`（以及 `ask` / `chat`）：

- 受维护者配置的总预算约束——每次请求语句数、每人每天次数与秒数、并发，ClickHouse 上还有
  引擎强制的扫描上限；超限时说清卡在哪一项，零 SQL；
- 在确认单上就能提醒区间末尾可能没有数据：默认靠维护者声明的更新节奏，零查询；维护者开启
  后可以在确认前做一次只作参考的新鲜度探测；
- 把同一个人在同一业务空间上次确认过的口径作为「历史选择」预填，写明日期，失效即不沿用；
- 能回答「上个月广告渠道的新增用户」这类取值过滤问题。

完整方案见 [切片 1D/1E 技术方案](../specs/workflow-slice-1d1e-2026-09.md)。

## Decisions so far

<!-- one line per closed ticket -->

- [T40 — 统一预算与准入](tickets/40-budget-and-admission.md) — 上限只在配置里；按语句计，flow 与
  agent 共用一本账；准入在占幂等键之前，重放不受额度影响；扫描上限只有 ClickHouse 做得到，就只
  在 ClickHouse 上允许配置。ADR-011。
- [T41 — 确认前的新鲜度提醒](tickets/41-freshness-before-confirmation.md) — 默认靠维护者声明的
  更新节奏、确认前零查询；探测由维护者开启，只许编译器的 `MAX()`、缓存、计预算；提醒不进哈希，
  结果以执行时为准；声明顺带成了加载监控。ADR-010 收窄 I2。
- [T42 — 沿用上次确认过的选择](tickets/42-history-reuse.md) — 「历史选择」写明日期、进哈希；只属于
  一个人在一个空间；只填缺口，不盖文档与问题；映射指纹、选项、文档复查、期限任一变化就不沿用，且不
  解释；`--yes` 不预填。ADR-012。
